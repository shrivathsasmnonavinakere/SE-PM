# AnnaDhata Codebase Audit (`PROJECT_AUDIT.md`)

**Audit Date:** 2026-11-12  
**Scope:** Full-stack inspection of AnnaDhata (`backend/` Java 21 / Spring Boot 3.2.5 / MongoDB, `frontend/` React 18 / TypeScript / Vite / Tailwind CSS).

---

## 1. Executive Summary of Existing Architecture
The existing repository provides a solid baseline implementation featuring:
- **Backend:** Spring Boot 3.2.5 REST API with stateless JWT authentication (`jjwt 0.12.5`), BCrypt password hashing, Spring Data MongoDB (with an automatic in-JVM `mongo-java-server` fallback on port 27017), Google Gemini 1.5 Flash integration with deterministic fallback (`GeminiAIService`), Haversine geospatial math (`GeoUtils`), scheduled expiry sweeps (`DonationService`), and 12 passing unit tests.
- **Frontend:** React 18 + TypeScript + Vite SPA using React Router v6, Axios interceptors, React Context (`AuthContext`), Tailwind CSS, Leaflet (`react-leaflet`), Recharts, and Lucide icons across 25 pages covering Public, Donor, Receiver, and Admin portals.

However, deep code inspection uncovered **multiple critical security vulnerabilities, backend/frontend integration bugs, fake multiplier/hardcoded analytics strings, state-machine defects, and missing test infrastructure** that must be fixed before upgrading the platform.

## 2. Critical Security Issues Found

| # | Severity | Component / File | Finding | Remediation Plan |
|---|---|---|---|---|
| S-1 | **CRITICAL** | `AuthService.java:48`, `RegisterRequest.java:23` | **Self-Registration Privilege Escalation:** Public `POST /api/auth/register` accepts any `Role` in request body including `ROLE_ADMIN`, granting unauthenticated callers immediate full admin JWT access. | Reject `ROLE_ADMIN` on public registration with `403 Forbidden`; only permit `ROLE_DONOR`, `ROLE_RECEIVER`, and `ROLE_VOLUNTEER`. |
| S-2 | **HIGH** | `JwtAuthenticationFilter.java:49` | **Suspended Accounts Retain API Access:** `jwtService.isTokenValid(jwt, userDetails)` does not verify `userDetails.isEnabled() && userDetails.isAccountNonLocked()`. Already-issued JWTs continue authenticating suspended users (`active = false`). | Check `userDetails.isEnabled() && userDetails.isAccountNonLocked()` in `JwtAuthenticationFilter` and reject suspended tokens cleanly. Also add `DisabledException` / `LockedException` handlers in `GlobalExceptionHandler`. |
| S-3 | **HIGH** | `ClaimService.java:55-107` | **Unverified NGOs Can Claim Food:** `createClaim` never checks whether a `ROLE_RECEIVER` has `verificationStatus == VERIFIED`. Any unapproved NGO account can submit food claims immediately after signup. | Enforce `receiver.getVerificationStatus() == VerificationStatus.VERIFIED` (or Admin override) before permitting claim creation. |
| S-4 | **HIGH** | `ClaimController.java:90-96`, `DonationController.java:115-121` | **Insecure Direct Object Reference (IDOR):** `GET /api/claims/donation/{donationId}` and `GET /api/donations/{id}/matches` allow *any* authenticated `ROLE_DONOR` to view claims, matches, and private phone numbers of *another* donor's donation. | Enforce ownership verification (`donation.getDonorId().equals(currentUser.getId())`) or `ROLE_ADMIN` in service/controller methods. |
| S-5 | **MEDIUM** | `NotificationService.java:63-72` | **Notification Ownership Bypass (IDOR):** `markAsRead` silently returns another user's `Notification` document instead of rejecting when `recipientUserId` does not match `currentUser.getId()`. | Throw `ForbiddenException` if caller does not own the notification. |
| S-6 | **MEDIUM** | `DonationController.java:74-90` | **PII Exposure on Public Endpoints:** `/api/donations/public/available` and `/api/donations/public/{id}` return `donorPhone` to unauthenticated visitors. | Mask or omit `donorPhone` on unauthenticated public donation endpoints. |
| S-7 | **MEDIUM** | `SecurityConfig.java:51` | **Unrestricted Actuator Endpoints:** `.requestMatchers("/actuator/**").permitAll()` exposes sensitive diagnostic endpoints publicly instead of only `/actuator/health` and `/actuator/info`. | Restrict public actuator paths strictly to `/actuator/health` and `/actuator/info`; require `ROLE_ADMIN` for other `/actuator/**`. |
| S-8 | **MEDIUM** | `AiController.java:53-65` | **Missing Role Authorization & Entity Mass Assignment:** `GET /api/ai/analytics-report` lacks `ROLE_ADMIN` restriction; `POST /api/ai/screen-safety` binds directly to the MongoDB `@Document` `Donation` entity; `/api/ai/chat` rejects public visitors with 403 even though `AiChatWidget` renders globally. | Restrict `/analytics-report` to `ROLE_ADMIN`, replace raw entity binding with a validated `AiSafetyScreenRequest` DTO, and expose a safe public `/api/ai/public/chat` FAQ endpoint for unauthenticated visitors. |
| S-9 | **MEDIUM** | `DonationService.java:137` | **Workflow Bypass in `updateDonation`:** Donors can pass arbitrary `DonationStatus` (such as `COMPLETED` or `CLAIMED`) to `PUT /api/donations/{id}`, bypassing claims, safety checks, and audit logging. | Disallow transitioning directly to `CLAIMED`, `PICKUP_SCHEDULED`, `PICKED_UP`, `COMPLETED`, or `PARTIALLY_CLAIMED` through `updateDonation`. |
| S-10 | **LOW-MED** | `GlobalExceptionHandler.java:77-81` | **Missing `UnauthorizedException` Handler & Error Leakage:** `UnauthorizedException` returns HTTP `500` with raw `ex.getMessage()`. Unhandled exceptions also echo internal `ex.getMessage()` directly to callers. | Add `@ExceptionHandler(UnauthorizedException.class)` returning HTTP `401`; return a sanitized generic error message for unhandled `500` errors. |

## 3. Functional Bugs, Data Integrity Defects & Integration Mismatches Found

| # | Area | Component / File | Finding | Remediation Plan |
|---|---|---|---|---|
| B-1 | **API Integration** | `FoodCategory.java`, `DonationController.java:83,94`, `AvailableDonationsPage.tsx:65` | **Category Filter 500 Crash:** Frontend sends display labels (`?category=Cooked food`), but Spring MVC `@RequestParam FoodCategory` relies on `Enum.valueOf()`, throwing `MethodArgumentTypeMismatchException` because the enum identifier is `COOKED_FOOD`. | Add a Spring Web `Converter<String, FoodCategory>` calling `FoodCategory.fromString(source)` via `WebMvcConfigurer`. |
| B-2 | **Frontend Timezone** | `CreateDonationPage.tsx:50-51`, `AvailableDonationsPage.tsx:79`, `DonationMapPage.tsx:42`, `ReceiverDashboard.tsx:56` | **`datetime-local` UTC Shift Bug:** Forms initialize `<input type="datetime-local">` using `.toISOString().slice(0, 16)`, which strips timezone info and displays UTC time as local time. In positive UTC offsets like IST (`+05:30`), submitting default times sends deadlines 1.5 hours *in the past*, failing backend validation (`Pickup deadline must be in the future`). | Replace `.toISOString().slice(0, 16)` with a proper local-time formatter helper (`formatLocalDateTimeInput`) across all date-time inputs. |
| B-3 | **Frontend Auth / Public** | `ImpactDashboardPage.tsx:43` | **Public Impact Page Returns 403 for Guests:** The unauthenticated `/impact` route calls `/api/impact/summary` (which requires JWT) instead of `/api/impact/public/summary`. Guests see `0 kg` and empty charts. | Use `impactApi.getPublicSummary()` (or conditional auth) on `ImpactDashboardPage`. |
| B-4 | **Frontend / Admin** | `DonationModerationPage.tsx:27` | **Admin Moderation Only Shows Available Donations:** Calls `donationApi.getPublicAvailable()` instead of an admin all-donations endpoint, making `CLAIMED`, `COMPLETED`, `EXPIRED`, and `CANCELLED` tabs permanently empty. | Add `GET /api/admin/donations` returning all listings across all statuses and connect `DonationModerationPage`. |
| B-5 | **Claim State Machine** | `ClaimService.java:166-245` | **State Transitions & Double-Counting Impact:** `markCompleted` and `markPickedUp` do not validate prior claim status (`APPROVED`), allowing duplicate `/complete` calls to record double `ImpactRecord` rows. `markPickedUp` does not even transition `ClaimStatus` to `PICKED_UP` or set pickup timestamps. `createClaim` does not validate `claimedQuantity <= remainingQuantity` or block `HIGH_RISK` donations without review. | Enforce strict state transitions (`PENDING -> APPROVED/REJECTED -> PICKED_UP -> COMPLETED`), enforce unique impact recording per `claimId`, validate quantities and safety rules cleanly. |
| B-6 | **Fake / Hardcoded Analytics** | `ImpactService.java:110`, `AnalyticsService.java:62`, `GeminiAIService.java:263-264` | **Hardcoded Metrics:** `ImpactService` fabricates `totalFoodDonatedKg = totalRedistributedKg * 1.15`; `AnalyticsService` hardcodes `"Central Redistribution Zone"`; `GeminiAIService` hardcodes `"Vegetables and Fruits"` and `"19:00 - 22:30"`. | Compute true donated kg from `DonationRepository`, compute real peak donation hours, highest surplus zones, and actual unmet demand deficits from `ReceiverNeedRepository` vs `DonationRepository`. |
| B-7 | **AI Safety Rule Violation** | `GeminiAIService.java:152-241` | **AI Overwrites Deterministic Safety Concerns:** Gemini returning `LOW_RISK` overwrites `REVIEW_REQUIRED` flags raised by deterministic checks. Deterministic parser also lacks spoilage/contamination keyword checks when `GEMINI_API_KEY` is unset. | Guarantee deterministic safety severity acts as a minimum floor (AI may escalate risk, never downgrade); add deterministic hazard keyword detection and prep/deadline time parsing. |
| B-8 | **Matching & N+1 Queries** | `MatchingService.java:68-153`, `AdminService.java:104` | **Unverified Receivers Matched + N+1 Queries:** `MatchingService` matches unverified or suspended NGOs and performs per-need `userRepository.findById` queries; `AdminService.getAllUsers()` queries `findById` N times in a loop. NGOs also have no UI on `ProfilePage` to submit verification proof URLs. | Filter to `VERIFIED` + `active` receivers, bulk-load users cleanly, incorporate pickup window & urgency checks, and add verification doc management on `ProfilePage` + `RegisterPage`. |
| B-9 | **Donation Cancellation** | `DonationService.java:145-160` | **Orphaned Pending Claims on Cancel:** Cancelling a donation leaves `PENDING`/`APPROVED` claims open without updating them or notifying claimants. | Automatically transition open claims on a cancelled donation to `CANCELLED` and notify affected NGOs (and assigned volunteers). |
| B-10 | **Frontend Session Sync** | `AuthContext.tsx:21-22, 47-49` | **Unsafe JSON Parse & Stale Session:** Uncaught `JSON.parse` on corrupted `localStorage`, and `refreshUser()` ignores 401 errors instead of calling `logout()`. | Add safe `try/catch` around cached user parse and automatically log out on `401` during session verification. |
| B-11 | **Testing & Tooling** | `backend/pom.xml`, `frontend/package.json` | **Test Runner & Sandbox Pipe Restrictions:** Dynamic ByteBuddy agent self-attachment for Mockito stalls under sandboxed Windows pipe restrictions unless passed as `-javaagent`; Frontend has zero unit/component tests configured. | Configure `maven-dependency-plugin:properties` + `-javaagent` in `maven-surefire-plugin` for reliable sandbox execution; add Vitest + React Testing Library setup in `frontend/package.json`. |

## 4. Planned Phase-by-Phase Execution Roadmap
- **Phase 1 (Immediate):** Fix all 10 security vulnerabilities and 11 functional/integration bugs above; verify existing 12 JUnit tests + frontend build pass.
- **Phase 2 (Backend Upgrades):** Implement Partial Food Distribution, QR Food Passport, Rescue Relay, AI Demand Heatmap, Volunteer Network, Trust & Reliability Score, and enhanced Gemini AI pipelines + comprehensive JUnit tests.
- **Phase 3 (Frontend Upgrades):** Connect all new endpoints with updated dashboards, Partial distribution UI, QR code generation & scanner UI, Rescue Relay workflow UI, Interactive Demand Heatmap page, Volunteer Dispatch Portal, and Transparent Trust Score cards + Vitest tests.
- **Phase 4 (Final Verification & Docs):** Run full backend & frontend test suites, run production builds, perform end-to-end API & UI verification with running servers, and update all documentation.
